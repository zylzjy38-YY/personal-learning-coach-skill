# 学习进度记录

平台允许文件读写且用户正在进行长期课程时，将进度保存在当前学习项目的：

```text
.learning/personal-learning-progress.md
```

不要把进度文件写进 Skill 安装目录。Skill 是可复用规则，进度属于具体课程。

## 记录格式

```markdown
# Learning Progress

- Subject:
- Course goal:
- Target standard or competition:
- Current primary stage: 1 | 2 | 3 | 4 | 5
- Current unit:
- Last updated:

## Stage map
- Stage 1 scope:
- Stage 2 scope:
- Stage 3 scope:
- Stage 4 scope:
- Stage 5 scope:

## Current stage coverage
- [核心模块]: not_started | learning | independently_demonstrated

## Demonstrated mastery
- [知识点]: [能独立完成的证据]

## In progress
- [知识点]: [当前缺口或所需提示级别]

## Confirmed error patterns
- [错误类型]: [学习者确认的原因和防错检查]

## Methods already used
- [方法]: [适用条件与掌握程度]

## Stage-gate history
- [日期 / 阶段]: [总分、各模块结果、提示使用、结论]

## Remediation plan
- [薄弱模块]: [补讲、针对练习、复测条件]

## Next task
- [下一道完整题或下一学习目标]
```

## 更新纪律

- 只记录由独立作答、解释、测试或迁移题证明的掌握，不记录空泛的“已了解”。
- 错因必须来自学习者说明或可观察的步骤，不猜测心理原因。
- 保存下一题的完整目标，但不要提前写出答案或提示。
- 晋级测试必须保存覆盖表、评分证据和是否独立完成；不能只写“通过”或“未通过”。
- 阶段未通过时保留原结果，记录补弱和复测；不要通过删除失败记录制造连续进步。
- 每次只做小幅更新，保留仍有效的历史信息。
- 平台无文件权限时，在会话末尾输出一段可复制的同格式摘要，并说明尚未持久保存。
