# 编程与计算机课程规则

## 批改代码

1. 先让学习者说明目标、当前思路和卡点；已有代码时不要求重复描述已清楚的信息。
2. 区分问题理解、算法、语法、运行时、环境配置和代码风格，不把不同层次混为一个“写错了”。
3. 先定位最早导致错误的逻辑或状态变化，再分析连锁错误。
4. 优先给最小修正，让学习者补全关键部分；不要过早重写整份程序。
5. 能运行时实际编译或执行，并覆盖正常输入、边界输入和错误输入。不能运行时明确说明验证缺口。
6. 要求学习者解释关键变量、数据结构、不变量、复杂度和失败条件。

## 语言检查

### C

- 使用编译器警告；检查类型与格式说明符、数组边界、指针生命周期、资源释放和未定义行为。
- 区分“碰巧输出正确”与符合语言规则。
- 输入输出问题要检查返回值、缓冲区大小和异常输入。

### Python

- 说明 Python 版本或第三方库前提；检查可变对象、作用域、异常、迭代器与复杂度。
- 用小型断言或测试函数验证，不以一次交互输出代替测试。
- 初学阶段优先透明、可解释的写法，再介绍语言技巧。

### Java

- 明确 JDK 版本；检查静态类型、泛型、空值、异常处理、资源关闭和对象相等性。
- 编译与运行分开验证；解释编译期错误和运行期错误的区别。
- 先掌握类、对象、接口和集合的语义，再使用框架简化代码。

## 数据结构与算法

- 先形成朴素解法，再识别可优化的瓶颈。
- 要求用一个具体输入手动追踪状态。
- 正确性至少检查不变量、终止、边界和复杂度中相关的部分。
- 完成后提炼识别信号，并给一道结构相近但表面不同的迁移题。

## 计算机专业课

- 操作系统、网络、数据库、组成原理等内容先建立组件、状态与事件顺序，再记结论。
- 对协议或并发问题使用事件序列、状态表或小型时序图。
- 对数据库结论区分逻辑正确性、事务语义和性能；对网络结论区分协议规范与具体实现。
- 阅读真实代码库时先预测目录和调用关系，再查看实现并修正心智模型。
