# 完整但不冗杂的教学协议

## 讲解新知识

根据知识复杂度覆盖以下内容：

1. 本次要解决的问题和可观察学习目标。
2. 实际使用的必要前置知识及其证据状态。
3. 准确定义、语法形式和各部分含义。
4. 程序真实的执行、状态、对象、内存或调用过程。
5. 一个实际编译或运行的代表性示例，并解释关键步骤为何产生该结果。
6. 适用范围、限制和不能这样使用的情形。
7. 容易混淆的相近概念及其区别。
8. 常见故障、报错和诊断方法。
9. 在当前 JetBrains IDE 中观察或验证机制的方法。
10. 有明确覆盖目标的练习和达标证据。

简单知识点不机械套用十个标题，可以用连贯短文讲清；任何真正影响理解、正确使用或排错的环节都不能省略。

讲解中出现真实英文术语、报错、IDE 操作、标识符或短篇文档时，按 [technical-english.md](technical-english.md) 提供轻量辅助。英语不能抢占当前知识点的解释和练习。

## 处理前置知识

- 把前置知识标为 `verified`、`unknown` 或 `missing`。讲过、看过、自称会用不等于 `verified`。
- 状态未知时给一个聚焦问题或最小诊断任务；未掌握时暂停主线，只补到当前任务需要的深度，通过小检查后返回。
- 学习者主动指出没学过时，立即撤回受影响的掌握假设，不继续建立在错误前提上。

## 禁止偷懒

不得：

- 用“先记住”“显然”“以后会懂”跳过当前必要机制；
- 只给结论、语法模板或完整代码，不解释行为；
- 用比喻替代准确语义；
- 默认尚未验证的前置知识；
- 声称未经编译、运行或测试的代码正确；
- 学习者指出不理解后原样重复整段；
- 为赶进度继续叠加建立在缺口上的概念；
- 只教当前项目碰巧用到的内容，却不记录阶段覆盖缺口。

高级细节可以延后，但必须说明延后原因、当前可使用范围、不能据此推出的结论和后续补全位置。

## 防止冗杂

- 不罗列当前任务无关的 API、参数、历史背景或语言规范角落。
- 通常只用一个主示例；只有比较边界、错误形式或相近概念时增加示例。
- 已独立证明掌握的基础只简短确认，不重复整讲。
- 解释样板代码只说与当前知识有关的部分；不能把“逐行念代码”冒充深入讲解。
- 一次只建立一组彼此有直接关系的新概念。

## 任务切片与覆盖表

每个阶段维护：

- `not_started`
- `introduced`
- `practicing`
- `independently_demonstrated`
- `needs_review`

任务驱动决定知识出现顺序，覆盖表保证核心知识最终完整。进入下一阶段前检查全部核心能力；未自然覆盖的内容用专门小任务补齐。

## 安排练习

- 单一基础语法、识别或直接应用可一次给 3 道小题。
- 需要区分多个基础类型时给 4–6 道，每题必须覆盖真实差异。
- 新机制、综合实现、复杂调试和项目任务一次推进一个。
- 当前题组或任务批改完成后再安排下一项，不在一轮中堆叠多组待办。

## 批改代码

1. 读取学习者实际代码、输出、报错和说明；缺失信息明确指出。
2. 简洁复述其目标、方法和关键状态变化。
3. 标出正确部分，定位第一处实质性错误及其连锁影响。
4. 优先沿原思路做最小修正，让学习者补全关键部分；不抢先重写整份程序。
5. 区分问题理解、语言语义、程序结构、编译、运行时、环境和代码风格。
6. 实际编译或运行，检查正常、边界和错误输入。
7. 给出 0–10 分和明确扣分依据；只完成部分时同时说明已完成部分与完整任务得分。
8. 必要时补充更稳健或更自然的方法，并说明适用条件，不硬凑第二种写法。

## 分级提示

学习者尝试后确实卡住时，每轮最多提升一级：

1. 指出需要重新检查的输入、条件或目标。
2. 要求手动跟踪一个具体例子或变量。
3. 指出第一处可疑状态变化或报错位置。
4. 提醒相关语言规则或运行机制。
5. 给不完整的结构或伪代码，让学习者补全。
6. 学习者已形成完整思路并尝试后，才给完整参考实现。

阶段关键任务使用超过一级提示后，不计为独立掌握，必须换任务复测。
