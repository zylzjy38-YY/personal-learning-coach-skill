# 系统与资源管理语言路线

覆盖 C、C++、Rust。共同主线是资源与生命周期，但三门语言的语义和达标证据必须分别定义。

## C

C 为第一顺位语言。重点建立：

- 编译、链接和程序入口的基本模型；
- 整数与浮点类型、转换和溢出边界；
- 数组、指针、地址、长度与字符串终止符；
- 函数调用、参数传递、作用域和存储期；
- 结构体、枚举、头文件与源文件组织；
- 栈、堆、动态分配、释放和资源所有责任；
- 输入输出返回值、缓冲区大小和错误码；
- 未定义行为与“碰巧输出正确”的区别。

典型故障：数组越界、空指针或悬空指针、段错误、未初始化值、重复释放和泄漏。使用 CLion、实际编译器警告、Debugger 和可用的 Sanitizer 复现与验证。

适合的最终项目包括文件持久化的控制台管理工具、日志分析器、索引器或明确格式的解析工具。项目不得以高级数据结构或竞赛题作为主要难度来源。

## C++

C++ 为第二顺位语言。不能把它当作“带类的 C”，也不能默认掌握 C 就掌握 C++。

重点建立：

- 值语义、引用、`const` 和对象生命周期；
- 构造、析构与 RAII；
- 标准字符串与容器；
- 资源所有权、智能指针和异常安全；
- 复制、移动及其可观察效果；
- 类、组合、接口式抽象、模板与类型推导；
- 源文件组织、编译、链接和 CMake。

典型故障：越界、悬空引用、use-after-free、对象切片、错误移动、资源泄漏和异常路径清理。使用 CLion、Debugger、编译器诊断和 Sanitizer。

## Rust

Rust 为扩展支持语言。重点建立：

- 所有权、移动、复制和借用；
- 生命周期与编译器约束；
- `Option`、`Result`、模式匹配和错误传播；
- struct、enum、trait、泛型和模块；
- `panic` 与可恢复错误的边界；
- Cargo、测试、依赖与文档。

典型故障包括所有权或生命周期编译错误、越界导致的 `panic`、错误的 `unwrap` 和错误传播遗漏。使用 RustRover 或 CLion、编译器诊断和 backtrace。

## 跨语言比较纪律

只有在学习者已经掌握相关概念时，才比较 C 的手动释放、C++ 的 RAII 和 Rust 的所有权。比较必须说明语义差异和适用边界，不能用另一门语言的规则解释当前语言。
