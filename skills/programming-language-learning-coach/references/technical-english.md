# 轻量嵌入式技术英语

技术英语是编程学习的附带收益，不是课程中心。只利用当前本来就会遇到的术语、报错、IDE 界面、标识符和短篇官方文档提供即时帮助。

## 首次出现的术语

- 保留英文原词，并给出它在当前技术语境中的准确中文含义。
- 只解释影响当前概念、代码或排错的词义，不罗列词典中的其他含义。
- 必要时指出常见缩写或构词关系，帮助以后识别；默认不展开音标、通用语法或日常英语。
- 一次学习回合通常只积累 3–5 个真正重要且会再次出现的词，不为凑数量扩大词表。

例如：

```text
mutable：可变的，表示对象创建后内部状态仍可修改
immutable：不可变的，表示对象创建后不能原地改变其值
```

## 阅读报错

保留错误原文，不先用整句中文替换。引导学习者依次识别：

1. 错误或异常类型；
2. 发生了什么动作；
3. 涉及什么对象或类型；
4. 文件、行号和调用位置；
5. 哪些词真正影响根因判断。

例如 `TypeError: unsupported operand type(s)`，只需结合当前错误解释 `TypeError`、`unsupported` 和 `operand`，重点理解“什么操作不支持什么类型”，不要求背完整句子。

英语误读导致技术错误时，先解决编程问题，再补充关键词和阅读线索。不能为了词汇练习延迟故障修复。

## IDE 与命名

- JetBrains 菜单、调试面板和工具词首次使用时给中英对应，例如 `Breakpoint`（断点）、`Call Stack`（调用栈）、`Watch`（监视表达式）。
- 逐渐训练简洁、有意义的英文变量名、函数名和模块名，并解释命名依据。
- 不强迫初学者写复杂英文句子，也不使用中文标识符回避会反复出现的基础技术词。

## 阅读短篇官方文档

- 每次只选择当前任务真正需要的一小段。
- 先识别代码、参数、条件词、动作词和句子功能，再用中文准确复述。
- 不逐词翻译长文，不把文档阅读扩展成通用英语语法课。
- 随着学习者能够独立识别常见结构，逐渐减少中文辅助；新的复杂术语仍需解释。

## 复现与进度

- 旧词通过后续代码、报错、IDE 和文档自然复现；只在证据显示遗忘时低频回顾。
- 可以在当前语言进度文件中记录核心术语、能够独立读懂的报错类型和短文档阅读证据。
- 不建立英语阶段，不单独评分，不把词汇量作为编程掌握证据，也不能因英语薄弱阻止编程晋级。
- 学习者主动要求系统英语、发音或日常英语时，说明这超出本 Skill 的附带目标，再按其请求另行处理。
