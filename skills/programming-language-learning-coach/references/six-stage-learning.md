# 六阶段编程语言学习路线

## 基本原则

- 阶段表示可观察能力，不表示看完多少章节或学习多少小时。
- 每门语言分别建立覆盖表、阶段结论和进度文件。
- 学过另一门语言只能减少已验证共通知识的重复讲解，不能直接授予当前语言的掌握状态。
- 每阶段以真实产出、解释、调试和测试证据验收。

## 第一阶段：基础语法过关

目标：能用核心语法独立写出小型程序，知道程序如何编译或运行，能读基础错误信息。

教学内容通过任务切片覆盖变量与类型、表达式、控制流、函数、字符串、基础容器、输入输出和输入校验，不按语言手册顺序罗列。

达标证据：独立完成一个由多个函数组成、包含输入校验的未见控制台任务，并修复一个基础故障。

## 第二阶段：程序拆解与数据建模

目标：能把需求拆成职责清晰的函数、模块、类或结构体，选择合适的数据表示并处理错误。

教学重点：模块边界、参数与返回值、状态管理、数据表示、代码阅读、基本测试和重构。每门语言最迟在本阶段主动安排一次受控经典故障或异常，让学习者开始阅读调用链。

达标证据：把混乱程序重构为多个清晰单元，补充测试，并解释拆分依据。

## 第三阶段：语言核心机制

目标：形成符合该语言的运行时心智模型，能解释程序为何如此运行、对象或资源由谁管理以及机制何时失效。

教学重点由当前语言参考文件决定。要求手动追踪状态、预测结果，并修复因错误心智模型产生的问题。

达标证据：独立完成语言专属状态追踪、机制解释和错误修复任务。

## 第四阶段：故障诊断与可靠性

目标：能独立复现和定位未见故障，使用调用栈、调试器和测试证明修复有效。

必须完成：复现 → 读取错误与调用栈 → 定位第一处根因 → 最小修复 → 回归测试。根据语言使用 Sanitizer、backtrace、异常链或异步调用栈等工具。

达标证据：在没有实质性定位提示的情况下完成一个陌生故障项目。接受提示完成时必须换项目复测。

## 第五阶段：工程化与语言生态

目标：能从干净环境构建、运行和维护具有多模块、依赖、测试、配置和持久化的中型项目。

教学重点：构建工具、依赖管理、环境隔离、测试、日志、配置、文件持久化、序列化、官方文档检索、重构和基本性能检查。框架只按项目需要引入，不替代语言核心。

达标证据：项目能够由明确步骤重新构建和运行；学习者能解释 IDE 自动生成的关键配置。

## 第六阶段：独立交付真实项目

目标：独立把真实需求转化为可运行、可测试、可维护的程序。

项目必须具有实际用途、明确环境、错误处理、测试和可复现构建，通常包含本地持久化或受控外部接口。不能逐步照着教程拼装，也不强制所有语言实现同一种项目。

最终验收：

1. 独立实现主要功能；
2. 说明设计和关键语言机制；
3. 诊断真实故障并增加回归测试；
4. 完成一个未提前告知的小型变更或维护任务；
5. 重构明显混乱的代码并重新验证。

该阶段只证明能够独立使用该语言交付和维护程序，不等同于算法竞赛水平或资深工程师水平。

## 日常推进

- 阶段内部按覆盖表和实际表现选取下一任务，不按固定课时推进。
- 当前知识正确且能解释依据时，略微提高综合或迁移要求。
- 方法正确但局部执行错误时，给同层级针对练习。
- 概念或运行机制错误时，退回最小必要知识并复测。
- 达到阶段末尾时停止添加零散新知识，先执行正式阶段测试。
