# JetBrains 工具教学规则

## 工具映射

- C/C++：CLion。
- Rust：RustRover 或 CLion。
- Java：IntelliJ IDEA。
- C#：Rider。
- Python：PyCharm。
- JavaScript：WebStorm。

优先使用学习者已有的 JetBrains 订阅和已安装产品。会员资格不等于软件、SDK、编译器或解释器已正确安装；缺失时先识别具体缺口。复杂安装、权限或系统环境问题转交计算机实用基础 Skill。

## IDE 不能替代工具链理解

- 首次运行时说明 IDE 实际调用的编译器、解释器、JDK、.NET SDK、Node.js、构建工具或测试运行器。
- 学习者至少能识别 Run Configuration、工作目录、环境变量、依赖环境和构建产物。
- IDE 成功运行但命令行失败，或两者输出不同，必须比较实际环境与参数，不能只说“IDE 有问题”。
- 不要求初学者脱离 IDE 完成全部工作，但关键命令和错误来源不能被按钮遮蔽。
- 常用英文界面词首次出现时保留原文并给出简短中文对应，例如 `Run`、`Debug`、`Breakpoint`、`Call Stack` 和 `Watch`；按 [technical-english.md](technical-english.md) 控制数量，不把 IDE 教学变成菜单词汇表。

## 分阶段使用

### 第一阶段

会创建项目、选择正确语言环境、运行程序、查看标准输入输出和错误面板，理解最基本的项目与源文件关系。

### 第二和第三阶段

使用导航、查找引用、重命名和安全重构理解程序结构；通过断点、单步、变量观察和调用帧验证状态与语言机制。

### 第四阶段

必须使用 Debugger、Call Stack、Breakpoints、Watches、异常断点及语言适用的 Sanitizer 或 backtrace。学习者先预测调用链，再用工具核对并修正心智模型。

### 第五和第六阶段

使用测试运行器、覆盖率、静态检查、重构、依赖视图和适用的性能分析工具。自动生成配置后解释关键设置，并验证项目能按文档在明确环境中重建。

## 验证纪律

- 截图只依据实际可见内容；看不清的配置或报错要求补充文本。
- 调试前先获得可重复步骤和最小输入，调试后用回归测试证明修复。
- 工具功能或界面随版本变化时核实 JetBrains 或对应语言工具链的当前官方资料，并标明版本。
